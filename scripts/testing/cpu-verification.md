## Evidence semantics and current result

`environment.json` records `requestedDelegate`, `productionDelegate: GPU`, build variant and unverified backend. `measurements.json` records requested mode and the delegates actually observed in `createFromOptions` separately. Mismatch is an evidence error and cannot establish successful inference. The browser tests independently require the requested option for positive and negative cases. WebGL renderer (currently SwiftShader) is reported separately: a software GPU renderer is not the SDK's CPU delegate. Requested/observed CPU options with model fetch failure do not prove task initialization, CPU kernel execution or CPU performance. The SDK's internal backend is not introspected.

Two real-SDK CPU initialization-failure diagnostics passed in development: actual option CPU, intended locally controlled HTTP503, zero inference calls/successes/results. All six inference scenarios remain **BLOCKED** and the supported CPU command exits2. Models have no bytes or reviewed size/SHA256 pins; original CONNECT403 restrictions remain. Positive cup/person/mask acceptance, first-frame/stale/lifecycle/model-switch/resource checks remain unexecuted on real CPU models. The full six-case matrix remains EfficientDet-Lite0/Selfie Segmenter × VideoFrame/owned Canvas/live HTMLVideoElement. Live-video latency stays unavailable/unbound. Controlled native streams are not physical cameras.

The initial development CPU attempt exited1 because the build hook ran after TS erasure and could not find its anchor. It had zero completed diagnostics and no inference; it is an implementation failure, not an asset-block success. The hook order was corrected, an actual CPU-build regression added, and a new run exited2 with2diagnostic passes/6blocked/4not-run. Both original logs remain in ignored local artifacts. No failed run is relabelled successful. Final frozen-HEAD logs/results and CI source binding are supplied in the Draft PR checkpoint after commit; this document does not invent a future self hash.
