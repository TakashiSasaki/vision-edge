# Partial Mirage encoder and dense-head candidate

This follow-up to the isolated HConvGLU experiment exports the five-stage stem,
16 body blocks, 12 attention blocks, register tokens, gated level memory,
feature pyramid, and raw detection/prototype/coefficient heads. It is a
**candidate partial conversion**, not validated Mirage equivalence. All four
numerical experiments finish with **FAIL** at the unchanged tolerances.
`MIRAGE_ONNX_NOT_VALIDATED` remains enabled and native WASM remains the default.

## Implemented computation and weight mapping

The candidate follows the equations in the official
[Mirage article's Maths panel](https://cactuscompute.com/blog/mirage#inside-the-model),
[HConvGLU specification](https://cactuscompute.com/blog/hconvglu), and
[structured-perception article](https://cactuscompute.com/blog/structured-perception).
The Maths panel's equations are present in the page's serialized document, even
when the default diagram view omits them from a text scrape. The retrieved page,
decoded document and extracted equations are retained in `.cache/mirage-encoder/`.

`encoder_candidate.py` requires 452 named, finite FP32 tensors with exact shapes.
It covers the original 32/64/128/256/512 stem widths, learned spatial convolutions,
one-plus-scale RMS normalization with epsilon 1e-6, masked residuals, 512-channel
65-tap HConvGLUs, GRN, grouped-query attention and RoPE, 12 raw level gates,
nearest-neighbor feature pyramid, ten detection channels, and two 32-channel
instance-mask branches. Mathematically inactive boundary taps are zero-padded;
learned bands are folded using the previously checked matrix orientation.

All 583 original Safetensors rows remain inventoried. The new mapping marks 452
as used by the candidate and **131 as out of scope/unmapped**, including the
language/region-memory/tokenizer/reader computation and training-only tensors.
No missing learned weights are initialized, guessed or filled with random data.
Neither object naming nor OCR text is generated by this ONNX graph. Its masks
are raw prototypes/coefficients; proposal selection and mask rasterization are
explicit research postprocessing choices, not production integration.

The independent PyTorch candidate is the unchanged pinned Oasis forward code at
revision `75bf8f3047e88a21c10d1f4175450656704a3c1e`, source SHA-256
`ce84a5da7016d141269ecce6bcb4eabcfcaada74a2ff189856a4e94c3913ff62`.
The loader checks the complete file hash and compiles only audited forward
definitions. It executes neither the downloaded module's imports nor its
top-level program, training code or constructor. The graph candidate uses NCHW
pointwise convolution and folded mixers; Oasis uses NHWC matrix multiplication
and unfused band windows. Agreement with this third-party candidate alone does
not establish agreement with the official native implementation.

## Native archive reconstruction as a separate experiment

The original pinned files retain the previously verified full identities:

- `mirage.safetensors`: 216370504 bytes, SHA-256 `6ba97c5c1bef661c9b0c80782135682b38b4312fb33e0b645c93c10604bb16cd`.
- `mirage.cact`: 21611043 bytes, SHA-256 `4249a0f7515272ff76b9414bec17d7e7daf84b15b66c7fb4f17fce1e66f9f237`.
- Model revision: `76c1e9e53381aca8fc3843c636216c96ff220122`.

`archive_encoder_weights.py` obtains 392 floating-point scope tensors directly
from the checksum-verified archive. **388 FP16 and four FP32 entries** match
casts of the original tensor bytes exactly, with row-major reshape where the
archive flattens convolution kernels. One equal-valued scalar is disambiguated
by its verified encoder record position. The other **60 attention projections**
use the pinned Oasis candidate's CQ entry positions, checked against the actual
entry type, shape, group size, bit width and length. The decoder expands packed
LSB-first 2-bit indices, archive codebook values and FP16 group norms through an
independent natural-order Walsh butterfly. Synthetic golden controls and an
independent comparison with Oasis's dense-Hadamard decoder check the arithmetic.

This reconstructs stored weights for diagnostic comparison; it is not an
official native forward or an emulation of native activation quantization and
kernel approximations. It must not be used to attribute every remaining native
difference to weight quantization. The original-FP32 and archive-dequantized
experiments have different explicit weight provenance and separate ONNX hashes.

## Inputs and unresolved preprocessing choices

Ten immutable input images cover square/landscape/portrait blanks, small objects,
objects at boundaries, overlapping shapes, bitmap text, and a genuine multi-category
photo of a stop sign, pole, trees, cars and grass. The photo is the official
[COCO 231049 example](https://cactuscompute.com/mirage/coco-231049.jpg), 54865 bytes,
SHA-256 `327de5cf31c479b7f4a5ca73b8b757f534f2e31ff6c452348f72aee86fb5b49b`.
Its original dimensions are 342 by 512. Two separately named fixtures rotate it
to landscape and stretch it to a square. The stretched square is intentionally a
different input used to remove letterbox ambiguity, not a replacement for the
original failing portrait case. RGB hashes for all ten are manifest-pinned.

Both implementations receive identical candidate preprocessing bytes: Pillow
11.1.0 bilinear resizing, nearest-integer valid extent, top-left placement,
RGB/127.5-1 scaling, normalized zero fill, and ceil-at-stride valid masks.
Two independently exported padding choices are compared: symmetric 1/1 padding
and stride-two SAME 0/1 padding. RoPE uses the candidate's rows-first pairs16
layout with unrotated registers; level gates remain raw as in the published
formula. Native resizing/filtering details and all full-model choices have not
been exhaustively established.

## Numerical measurements

Each graph passes the full ONNX checker and runs only the explicitly selected
`CPUExecutionProvider`. Every image captures 66 checkpoints and compares ONNX
against both the independent Oasis candidate and the exporting Torch candidate:
1,320 comparisons per configuration, plus 280 isolated-mixer comparisons using
the actual reference activation inputs. All ONNX graphs and inputs are preserved
in the ignored cache. No WASM output supplies missing ONNX tensors.

| Weights | Padding | Captured comparisons PASS / FAIL | Local mixer PASS / FAIL |
| --- | --- | ---: | ---: |
| Original FP32 | symmetric | 1218 / **102** | 270 / **10** |
| Original FP32 | SAME | 733 / **587** | 269 / **11** |
| Archive-dequantized | symmetric | 1265 / **55** | 270 / **10** |
| Archive-dequantized | SAME | 838 / **482** | 269 / **11** |

All **400 stem checkpoint comparisons** across these experiments pass. This
verifies the candidate stem arithmetic against the selected references and
inputs, not the official runtime's unavailable stem intermediates.

For original FP32/symmetric, the first failed captured checkpoint in traversal
is `square_blank / oasis_vs_onnx / top_7`. For archive-dequantized/symmetric it is
`square_blank / oasis_vs_onnx / body_2`. These are **captured block checkpoints**,
not claims to have isolated the first primitive instruction inside those blocks.
The report separately records the first local-mixer failure. Primitive-level
localization remains incomplete.

Against Oasis, worst checkpoint absolute/RMS errors are 0.4794921875 / 0.01052134
for FP32/symmetric and 0.1416015625 / 0.004193584 for archive-dequantized/symmetric.
Some late residual tensors amplify small FP32 differences. The actual mixer
inputs reach absolute values **23.3903** with original-FP32/symmetric and
**28.1376** with original-FP32/SAME. Thus the previous amplitude-eight stress
failures cannot be dismissed as outside the observed activation range.

The existing criterion remains elementwise
`abs(actual-reference) <= 2e-4 + 2e-4*abs(reference)`. Relative errors retain the
`max(abs(reference),1e-6)` near-zero denominator. Reports include every shape,
dtype, maximum absolute/relative error, RMS and failed-element count. The
thresholds and old failing fixtures were not relaxed or removed. Every complete
configuration exits 1. Initial aborted runs and their raw failures are retained;
reports have explicit completion flags so a partial run cannot appear accepted.

`diagnose_encoder_mixer.py` further isolates `top_11/hconv` using the captured
inputs from the blank square and actual square photo. In the explicit FP32
ONNX graph, the first threshold failure is the output-band MatMul; the folded
graph first fails at its final output. On the photo, their worst final errors
are 0.021484375 and 0.015625 respectively. The same inputs, weights and equations
in FP64 pass all 24 stage comparisons at `atol=1e-8, rtol=1e-9`. The FP32
PyTorch reference itself differs from the rounded FP64 oracle enough to fail
the existing output threshold (18 elements on the photo, maximum error
0.005859375). Thus these local failures include FP32 reduction/rounding and
cancellation effects in the reference as well as the export. This is evidence
about this mixer, not primitive-level localization of the earlier full-model
`top_7` checkpoint failure. The diagnosis exits 1 and retains all failures;
FP64 success still does not accept FP32.

## Official native observations and measurable differences

The pinned 4.1.0 Linux x86_64 library is checked again before direct C-ABI
inference. Ten genuine `.cact` calls yield eight parseable JSON observations and
two invalid JSON failures (`score:-nan` in the portrait blank and original photo).
The capture exits 1, preserves both exact raw responses, and retains every case.
The comparison validates native model/library, options, language and input hashes,
rejects duplicate/incomplete cases, and never substitutes a different capture.

On the square photo, the independently observed diagnostics are:

| Candidate | Native object count | Candidate object count | Matched at IoU >=0.5 | Mean matched box IoU | Mean matched mask IoU |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP32/symmetric | 12 | 9 | 8 | 0.832285 | 0.851851 |
| Archive-dequantized/symmetric | 12 | 14 | 12 | 0.970254 | 0.815058 |
| FP32/SAME | 12 | 5 | 0 | null | null |
| Archive-dequantized/SAME | 12 | 7 | 0 | null | null |

The archive-dequantized/symmetric text-region box has IoU 1.0 and score difference
0.00082649; the largest matched object-score difference is 0.00443111. On the
rotated landscape photo, six of seven archive-dequantized/symmetric proposals
match seven native objects, with mean box IoU 0.926012 and mask IoU 0.848690.
These observations support symmetric padding for these cases. They do not
establish exact non-square preprocessing, equal proposal selection, mask parity,
or full native numerical equivalence.

Matching is greedy, one-to-one, class-agnostic maximum box IoU with threshold
0.5. Unmatched candidate and native objects are always counted. Mask IoU uses an
explicit 128-square original-image grid: native polygon union versus nearest
samples of candidate prototype/coefficients thresholded at >=0.5 and box-cropped.
It is a diagnostic raster comparison, not a native-resolution bitmap proof.
Some native outputs contain degenerate two-point outlines. Those exact outlines
are preserved with `INVALID_NATIVE_POLYGON` and null mask IoU; box metrics and
other valid masks remain measurable. Invalid masks are not silently converted
to empty masks or counted as successful matches. OCR text and object-name
agreement remain null because no ONNX reader or language decoder is exported.

## Reproduction and remaining work

Use the isolated environment and pinned requirements from the HConvGLU report.
Acquire the official photo with an explicit download, verify its pinned hash,
and supply the unchanged pinned Oasis `reference.py`. There is no automatic
download during npm startup or these numerical commands.

```sh
.cache/mirage-python/bin/python -m unittest discover -s scripts/mirage -p 'test_encoder_candidate.py' -v
.cache/mirage-python/bin/python scripts/mirage/capture_encoder_native.py --cact .cache/mirage-resume/mirage.cact --library .cache/mirage-resume/runtime/libcactus.so --photo .cache/mirage-encoder/coco-231049.jpg --output-dir .cache/mirage-native-new
.cache/mirage-python/bin/python scripts/mirage/verify_encoder_candidate.py --checkpoint .cache/mirage-resume/mirage.safetensors --config .cache/mirage-resume/config.json --oasis-reference .cache/mirage-resume/oasis-reference.py --photo .cache/mirage-encoder/coco-231049.jpg --cact .cache/mirage-resume/mirage.cact --native-report .cache/mirage-native-new/native.json --weights fp32 --padding symmetric --output-dir .cache/mirage-encoder-new
```

Use fresh output directories and retain complete stdout/stderr and exit status.
Repeat with `--weights cact-dequantized` and/or `--padding same` into separate
directories. Native capture currently exits 1 but completes its ten-case report;
inspect it before using it as diagnostic input. Every numerical configuration
also currently exits 1 and is not a successful acceptance test.

The new 11 model-free controls cover stride alignment, normalization, validity
masks, a CQ golden vector, weight rejection, preprocessing, external-source
integrity, one-to-one matching, invalid native polygons and capture contracts.
Together with the existing 21 controls, all 32 local controls pass. Hosted CI
now runs the six HConvGLU and 11 encoder controls in a separate pinned Python
environment with raw-log upload and no model downloads, alongside the existing
15 checkpoint/metadata controls and npm regressions.

Next steps are primitive-level FP32 localization, authoritative non-square
resize/mask behavior, native activation/kernel differences, proposal selection
and native-resolution mask comparison. Region memory, language decoder/tokenizer
and OCR reader remain unsupported. WebGPU remains NOT RUN because CPU/native
acceptance has not succeeded. No model is enabled, merged or deployed by these
research results.
