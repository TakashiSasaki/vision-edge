# Mirage ONNX fidelity and availability

## Current product behavior

The supported Mirage variant is the original, pinned `mirage.cact` archive
executed by the Cactus WebAssembly worker. `mirage-51m` is the default in the
application, model registry, and asset resolver.

`mirage-webgpu` remains visible as unavailable. No faithful Mirage ONNX artifact
has passed reference-output validation. Its task factories and asset resolver
reject with `MIRAGE_ONNX_NOT_VALIDATED` before acquisition or initialization,
including caller-provided model URLs and worker factories. The local ONNX route
returns HTTP 503 with `Cache-Control: no-store`, including when an old artifact
exists. Old files are preserved but cannot be served by that route.

The conversion CLI exits 1 with a structured unavailable diagnostic. It neither
downloads weights nor creates or overwrites a model. Successful construction of
an arbitrary ONNX graph is not evidence of Mirage equivalence.

## Why the previous graph was removed

The baseline is
[`e6bf2899fd2e9d916f3904d344171f167588b8d4`](https://github.com/TakashiSasaki/vision-edge/commit/e6bf2899fd2e9d916f3904d344171f167588b8d4).
Its builder mixed manually assigned edge/color filters with fragments of the
checkpoint, omitted most of the architecture, substituted sigmoid for the
HConvGLU GELU gate, and invented a fixed-label classification head. The server
and browser fallback called that builder without any learned weights.

A dependency-free audit of the baseline builder produced 243,454 bytes,
17 operator nodes, 20 initializers, and 60,298 FP32 scalar constants. Changing
the supplied `stemPw3`, `stemPw4`, `hconvValue`, `hconvOut`, `denseEdgeKernel`,
`denseMidKernel`, and `denseCoarseKernel` left the generated bytes identical.
This was a graph-construction check, not inference or an ONNX checker run.

The generic Walsh matrix, band-fusion, layout, and serialization helpers remain
available for research. The legacy decoder is explicitly unvalidated and its
production factory is blocked. Its fixed resolution, regression decoding,
heuristic labels, OCR-region extraction, and mask postprocessing must not be
used as an authoritative Mirage output contract.

## Frame ownership in the isolated decoder

The former counter advanced only when native enrichment ran, stopping at 1.
It also retained the first observations and could append old objects after the
requested confidence threshold changed.

The retained research decoder advances on every accepted frame. Enrichment on
frames 1, 5, 10, 15, and so on is awaited on the same owned canvas used to build
that call's ONNX input. Observations exist only within that call. Skipped or
failed enrichment does not reuse another frame's names, text, boxes, or masks.
Current confidence, OCR inclusion, and result limits apply before fusion.
Overlapping calls cannot overwrite the canvas; closing discards late results.
Replacing or detaching an idle owned native task closes it exactly once;
assigning the same task preserves it. The previous public observation-cache
seeding method was removed.

These fixture-level controls establish scheduling and ownership behavior only.
They do not validate the legacy decoder or a learned ONNX model.

## Missing authoritative implementation

The source investigation on 2026-11-11 inspected these official materials:

| Material | What it establishes |
| --- | --- |
| [Mirage Python frontend](https://github.com/cactus-compute/cactus/blob/bafcf7348607c89f30ff9fde8e59d20b76baa86f/cactus/agent/mirage.py) | Input/API handling and a call into `cactus_describe`; not the complete neural-network forward graph |
| [Artifact acquisition](https://github.com/cactus-compute/cactus/blob/bafcf7348607c89f30ff9fde8e59d20b76baa86f/cactus/agent/fetch.py) | Runtime/model revision and artifact identities |
| [Public architecture module](https://github.com/cactus-compute/cactus/blob/bafcf7348607c89f30ff9fde8e59d20b76baa86f/cactus/model/architecture.py) | Shared/text-model components; no complete artifact-matched Mirage graph found |
| [Public export module](https://github.com/cactus-compute/cactus/blob/bafcf7348607c89f30ff9fde8e59d20b76baa86f/cactus/model/export.py) | Existing exporters; no verified complete Mirage mapping found |
| [HConvGLU specification](https://cactuscompute.com/blog/hconvglu) | Exact sequency Walsh and learned band/GELU operations |
| [Structured perception](https://cactuscompute.com/blog/structured-perception) and [mask specification](https://cactuscompute.com/blog/instance-segmentation) | Architecture and geometry descriptions, not an exhaustive executable implementation |

The available native header exposes the complete `cactus_describe` call, not a
reference interface for corresponding intermediate tensors. The inspected
public `cactus-compute/engine` tree at
`2204770dfd8c85750aaa20d25b657194becfc4c4` did not supply the missing implementation.

[Upstream issue 189](https://github.com/cactus-compute/cactus/issues/189) also asks
where the 4.1.0 runtime source lives. At inspection it was open with no comments.
Its reporter attributes source commit
`89a1c50096bfb5b57031682d629cec95228385b9` to the runtime manifest. Commit lookups
in both official repositories returned no matching commit. The manifest
attribution is the reporter's evidence; the lookup failures were independently
checked. This does not prove the implementation is unavailable everywhere.

The original archive is pinned to model revision
`76c1e9e53381aca8fc3843c636216c96ff220122`. Existing native benchmark evidence
under `docs/verification/` remains historical and does not validate ONNX.

## Requirements before enabling a future exporter

1. Obtain a complete reference implementation tied to the exact checkpoint.
   Map the stem, body, attention, normalizations, level memory, feature pyramid,
   detection and mask heads. Full semantic/OCR equivalence also needs region
   memory, the language decoder/tokenizer, reader, and output assembly.
2. Pin config, checkpoint, reference source, runtime, converter, and ONNX
   identities. Validate every required tensor's actual dtype, shape, layout,
   and role; reject missing or unexpected data. Validate range responses if
   partial downloads are used. Never substitute synthetic tensors.
3. Specify exact preprocessing and postprocessing: interpolation, padding,
   normalization, validity masks, epsilons, coordinate units/rounding,
   proposal selection, mask sampling, and semantic/text decoding.
4. Export corresponding intermediate tensors from a reference run on immutable
   images. Compare the same floating-point weights and input tensors against
   ONNX CPU, locating the first divergent operation. Compare ONNX CPU with
   WebGPU only after that succeeds.
5. Measure the difference from the official quantized `.cact` runtime separately.
   FP32 source weights and the released mixed-precision quantization need not
   produce identical values.
6. Check boxes/scores, masks, names, OCR strings, and structured fields separately
   on non-square, blank, border/small-object, multi-object, and text fixtures.
   A detector-only export must be described and gated as that narrower scope.
7. Bind downloadable artifacts and cache keys to source/converter hashes and
   completed validation. Verify the exact served and browser-loaded bytes.

## Verification scope of this correction

New model-free controls cover blocked generation, the real CLI's nonzero exit,
network-free factory/resolver rejection, stale-cache GET/HEAD rejection, native
asset routing, UI availability, repeated-frame scheduling, current-request
filtering, immutable snapshots, overlap, recovery, and shutdown.

The repository lock was reconciled using npm because the baseline clean install
failed on missing platform-specific optional packages. The reconciliation added
60 entries and retained the existing 271 entries unchanged before the required
application patch-version update. Dependency declarations were not changed.

The baseline's automatic `prebuild` cleanup also deleted the entire `.cache`
directory and the production build when Playwright built its separate fixture
output. The automatic hook was removed: Vite cleans only its selected output
directory. Explicit `npm run clean` removes generated `dist` and `server.js`
while preserving model caches, verification logs, and browser reports. Isolated
controls exercise both real npm commands without deleting shared evidence.

No actual Mirage model inference, ONNX equivalence benchmark, or deployment is
established by these controls. The remaining source/mapping/reference gates
above must be satisfied before the ONNX variant becomes available.
