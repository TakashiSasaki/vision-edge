## Stream ownership and cancellation

App's camera start/stop/toggle and facing callbacks are stable useCallback
functions. `useCameraStream` owns the acquisition lifecycle independently of
models, settings and detection/frame rerenders. Only enabled state, requested
facing mode or target-ref identity can restart its effect. A committed latest
notification callback ref avoids reacquisition even if a caller changes onStop.

Every request closure owns its own stream. Cleanup marks it cancelled before
releasing anything. A getUserMedia result delivered after stop, replacement or
unmount is stopped immediately without attachment/playback. A stale rejection or
play completion cannot change state or stop the new session. Cleanup pauses and
detaches video only if srcObject is exactly the stream being released; it never
clears another session's stream. Every owned track is stopped, and its ended
listener removed. Repeated cleanup does not stop the owned stream twice.

Camera readiness waits for successful video.play(), separately from model ready
and video.readyState. Current acquisition/playback failures and a current native
track-ended event release the stream, publish a short Japanese error and notify
the App once. Original cause, request, facing mode and failure stage remain in
diagnostics/state. Missing camera APIs and synchronous API exceptions are handled.
There is no automatic retry loop; starting again creates a new request. A denied
camera error stays visible after the App transitions to stopped and can be dismissed.

The facingMode constraint remains `ideal`, with the inherited 1280x720 ideals and
audio disabled. That is a request, not proof the physical device honored it. The
SDK/browser cannot cancel an already pending native permission request here;
the obsolete stream is released as soon as it resolves.

## Model and inference connection

The App-owned model engine is not disposed when the camera stops. The small
`clearDetections()` method resets only temporal output/mask buffers, retaining
the ready model task and model generation. The canvas invalidates its local and
parent frame, selection feedback and visible overlay on camera session/readiness
or facing changes. This also prevents the engine's two-frame persistence from
reintroducing detections from the old scene after restart.

Inference requires current camera playback readiness, current model readiness
and a video frame. The existing queued callback is cancelled on camera-session
changes using the PR-02 cleanup mechanism. No new scheduler, worker, FPS algorithm,
tracking algorithm, dictionary/TTS change or model implementation is introduced.
The existing one drawOverlays closure exception remains; camera-ready/session/
facing captures are explicit dependencies rather than new lint suppressions.
