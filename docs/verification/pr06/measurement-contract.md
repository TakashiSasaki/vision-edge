# PR-06 measurement contract

These are observed **JavaScript wall intervals**, not CPU usage, GPU execution or utilization, camera FPS, physical display presentation, or camera-to-display latency. `performance.now()` is the default, injectable monotonic clock. Existing inference FPS, draw FPS and frame `processingMs` code, success eligibility, estimator, labels and 250 ms HUD cadence remain unchanged. Instrumentation adds cost inside their existing wall boundaries; it does not subtract or hide that cost.

## Pipeline trace and identity

`startFrameScheduler` bootstraps `arrive()` once when allowed. Both bootstrap and callbacks call captureInput; successful candidates pass alreadyConsumed, observe and reserve. Reserve creates one yielding setTimeout, not a FIFO. Execution acquires JobLock and **recaptures with captureInput(true)**. That recapture is checked for duplication again, observed, marked consumed before work, passed to the SDK wrapper, and released by its owning finish. Arrive temporaries are released in finally. Failed work still consumes its input. Stop never releases a running job's foreign lock/image.

Every capture attempt is timed, including null/invalid/duplicate/withheld observations and execution recaptures. Every `samePixels` call in both `observe` and `alreadyConsumed` is timed, including cheap null/dimension mismatch checks and duplicates that never infer. The original full RGBA bytes plus dimensions comparison is unchanged. No hashing, thinning, Worker, identity, mask, dictionary, TTS, or coordinate algorithm change is included.

Enabled scheduling attaches a generation symbol, job ID and **execution capture-attempt ID** to the actual input handed to work and adoption. A VideoFrame and the fallback private owned Canvas are immutable for the owning SDK call. The quality-counter path still hands the original live HTMLVideoElement to the SDK, as before; its actual-image latency is **unbound/not applicable**, not assigned the arrival time. No arrival PTS or metadata timestamp replaces the existing SDK `performance.now()` timestamp.

## Boundaries and inclusion

| Stage | One sample / boundaries | Inclusion / outcome |
| --- | --- | --- |
| capture | Entry to captureInput through raw capture return/throw | Includes VideoFrame creation, quality read or RGBA draw/read and optional private Canvas putImageData. Immediate disposal on invalid-frame/copy failure is contained here. No external samePixels or later release. Success means a source was obtained, even if later duplicate; null return is cancelled; throw is failed. |
| comparison | Entry/exit of each samePixels call | Includes all-byte every scan and cheap null/dimension checks. External to capture. No claim that every call scans all bytes. |
| queue | Successful setTimeout reservation to callback execution/lock acquisition, or stop cancellation | Actual measured timer wait, never assumed zero. A blocked lock is cancelled reservation; a successful reservation can still have a duplicate/invalid execution recapture. Latest candidate may change while waiting. |
| job | Lock acquired through owning input release completion, before lock release | Occupancy includes execution capture, comparisons, engine, adoption (including ordinary auto-TTS checks), input release. Successful means work resolved and adoption returned while valid; SDK/work/adoption throw is failed; withheld/duplicate execution and stop are cancelled; completion after current-generation rejection is stale. Does not imply a ready SDK result was adopted into the UI. |
| sdk | Immediately around synchronous detectForVideo / segmentForVideo | Includes any synchronous SDK work or blocking; underlying GPU scheduling is unknown. SDK success can coexist with stale/failed engine output. |
| postprocess | SDK return through transformations, plus filtering/smoothing | One **summed** sample per attempted transform. Segmenter's first segment includes getAsFloat32Array, mask Canvas/image allocation, full float scan/RGBA creation, putImageData, tight BBox; second includes filtering/smoothing. Result close is between them and excluded. Detector mapping/dictionary lookup/filter/smoothing is one span. Not executed after SDK throw; zero executed work is valid. |
| cleanup | Each owning source.release and segmentation-result.close invocation | Input release is external to engine/capture; result.close is internal to engine and external to postprocess. No-op release is an executed call, possibly 0 ms. Detector has no disposable result: no fabricated result-close sample. Initialization/model dispose/clearDetections are out of scope. Swallowed SDK close exceptions retain the product's warning/return behavior and have failed cleanup timing. |
| engine | Ready detectVideoFrame wrapper entry before its original SDK timestamp to return/throw cleanup | Inclusive SDK, postprocess, result close, fixed dimension/branch checks and measurement callback overhead. Readiness/unsupported-model returns before execution are not duration samples. SDK throw preserves the original exception/reset behavior. Reentrant output/lifecycle invalidation is stale. |
| draw | Actual synchronous shared Canvas renderer call (dimension/context/buffer setup, overlays and visible Canvas copy/clear) | Ends before first-draw bookkeeping, FPS collection, React state, onFrame notifications. Empty accepted objects still copy a valid empty overlay. A clear without a result is actual draw work, but adds no legacy draw FPS or latency. Failure recorded before stopping/resetting the UI. Repeated RAF draws are draw samples, not repeated latency samples. |
| latency | Actual execution immutable-input capture **start** through first successful matching visible Canvas copy completion | CaptureStart is the beginning of JS capture, not camera exposure or original source PTS. Queue wait ordinarily precedes this recapture and is outside the interval. Time between capture and SDK includes duplicate/observe checks; after SDK includes adoption and wait for RAF. Exactly one sample per accepted job. First-draw bookkeeping reads the completion clock immediately after the copy/draw measurement; its small observer/validation overhead is included. The endpoint is the successful return of the synchronous Canvas drawImage call (plus the immediate completion-clock/bookkeeping boundary), not completion of deferred raster/GPU/compositor work. Physical presentation remains unknown. |

**Do not sum overlapping stages.** Job contains execution capture/comparison/engine/adoption/input cleanup. Engine contains SDK/postprocess/result cleanup. Capture includes owned-copy work. Latency crosses capture/engine/part of draw and includes scheduling gaps; queue is generally outside it. Counts are per-stage executions, not interchangeable frame counts. For example there can be many capture/comparison samples per successful inference.

`captureDuty` is specifically **the sum of measured captureInput-only durations whose completion timestamp lies in the rolling window, divided by a fixed 5000 ms, times 100**. It includes all attempt outcomes. It excludes comparison outside captureInput, release and SDK. It is not the total observation cost or CPU utilization. Completed intervals are attributed whole to their completion window, not clipped at the left boundary; a long straddling capture may therefore include work before that boundary. No bucket approximation is used. Missing, unclocked, overflowed or truncated capture coverage makes the duty unavailable. Separate comparison/cleanup totals expose work outside capture. No sum of overlapping intervals is offered as total pipeline utilization.

## Statistics, clocks and bounded coverage

All ordinary snapshots use the inclusive completion-time window `[now - 5000, now]`. A sample exactly 5000 ms old remains until the next later snapshot. Same-timestamp events remain separate events. The service accepts finite nonnegative durations including **measured 0**. Invalid, negative, inverted or unmeasurable spans are missing, not zero. No execution/not-applicable has count 0 and null time statistics. Empty observed result sets show `観測なし`; no pipeline snapshot shows `未計測`.

For every stage and success/failed/cancelled/stale outcome separately:

- Count includes timed events with missing durations; `measured` and `missing` are separate.
- Mean, maximum and sum use all retained valid durations in the window (maximum 2048 per stage/outcome). Empty or overflowing aggregates are null.
- Median and p95 use the **latest up to 300 valid durations**, with `quantileCount / measured` displayed. An even median averages the middle pair; p95 uses nearest rank `ceil(0.95*n)-1`, with no interpolation.
- Each store is a fixed 2048-slot ring. If an in-window event was evicted, `truncated` stays true until the newest discarded timestamp leaves the window. Counts/sums/mean/max are then explicitly partial retained-event statistics, never labelled full-window totals. Quantiles have their own separate cap and coverage even without ring truncation.
- No data sorts during capture/comparison/draw RAF. Bounded snapshots and latest-300 sorts occur at the existing 250 ms HUD cadence. Snapshot/render preparation cost is included in the overhead experiment.

Invalid/negative/NaN/infinite/throwing clocks invalidate spans. A backwards clock is quarantined until it catches up to the last accepted clock; equal clocks are valid. A probe's clock epoch invalidates a span crossing a bad read even when a later read recovers. Invalid end timestamps cannot be placed in a rolling window: they increment the explicitly **generation cumulative**, saturating `unclocked` diagnostic instead. The entire snapshot is unavailable while its own clock is invalid/backwards. Statistical errors and observer/clock exceptions are caught at telemetry boundaries and do not become product inference exceptions or change SDK arguments/results/ownership.

One metrics instance belongs to one scheduler generation. Stop/camera/facing/model/request/threshold/retry transitions clear displayed statistics and replace the instance. Generation symbols reject old probe emissions and old input/result identities after reset. Retired running jobs record their final cancelled/stale occupancy and release only into their retired collector, never the replacement HUD. These retired diagnostics are not a cross-session history and are no longer displayed. Statistics/memory are bounded: at most 10 stages × 4 outcomes × 2048 entries, one 2048-entry outcome ring, a 64-entry result map, fixed counters and snapshot arrays. The scheduler still has one pending candidate, one timer stamp and one running owner, with no growing queue map.

## Results and retention

`accept` retains only identity/timestamps, never image bytes or SDK resources. A successful first draw must match the same generation and exact accepted identity object. It removes that job, records `first-draw`, and adds latency only if its immutable capture timestamps are valid. Live or unmeasurable capture adds `unbound` alongside first-draw. Repeated RAF copies cannot add another latency sample. Result references from prior generations cannot match replacement jobs even if local numeric IDs repeat.

Never-drawn outcomes are separate bounded rolling counters: `overwritten`, `cancelled`, `hidden`, `draw-failed`, `expired`, and `capacity`. First-draw and unbound overlap by definition; never sum them as distinct results. A failed copy stops this generation; retry creates a new generation and cannot later measure the failed old result. Hiding the page discards pending first-draw eligibility, including newly adopted hidden results. No 0 ms sample is invented for any discard.

Pending results expire **strictly after** 5000 ms from acceptance, checked on acceptance, discard, first draw and each HUD snapshot. Exactly-at-boundary results are eligible. Capacity overflow evicts the oldest retained job. Expiry/capacity counters are timestamped when detected and use the same bounded outcome ring/truncation flag. Invalid first-draw/discard clock removes matching eligibility and increments `unclocked`, not an invented outcome timestamp. A result for which acceptance itself had no valid clock is unclocked/unretained. The production UI normally holds at most one eligible result; the independent service also defends higher-rate/multiple-job callers.

Queue **measurement** retention is one constant-size reservation stamp, from timer reservation until its callback or stop cancellation; there is no queue map requiring age eviction. An arbitrarily delayed callback still records its actual wait, rather than expiring or cancelling product work. Stop closes it as a cancelled queue sample. Running input/JobLock ownership remains until the owning work finishes, however long that takes; instrumentation never introduces a product timeout or early release.

## Enabled / disabled and user interface

Supplying no instrumentation to scheduler/engine skips probe construction, measurement clock reads, capture/job identity allocation, sample allocation and aggregation. The experiment likewise omits draw probes, first-draw bookkeeping, statistics and detailed-panel updates in the disabled arm. Product SDK timestamp reads and product work remain. Both arms are the same production-compiled experiment build with the same resolution/input script/model double and checked actual processed/captured/full-array-compared/drawn counts.

The ordinary HUD labels are unchanged. Native collapsible details do not update camera, model, threshold, selection, speech or scheduler dependencies. The detailed panel lists unit, aggregation, coverage, meanings, inclusive boundaries and unavailable states; failure/cancellation/stale tables can be expanded independently. Opening/closing only changes DOM disclosure state. No synthetic SDK/experiment imports occur in the normal application entry; the existing explicit e2e SDK alias remains test-mode-only.
