## Real application reproduction

Read VisionCanvas and its tests, VisionEngine, coordinate types, camera hook,
CSS, Vite/Playwright configuration, SDK fixture and existing native-video tests.
The video and Canvas DOM rectangles coincide, both with `object-fit: contain`,
`object-position: 50% 50%`, no CSS transform, padding or element border. The
outer container has its own border. Canvas backing dimensions follow the
intrinsic video dimensions on drawing. BBoxes/polygons are normalized to that
intrinsic image; pixel masks are scaled to the full backing image. DPR is not
part of these normalized interfaces.

Inspected the real DOM before choosing the fix. Nominal responsive aspect-ratio
classes do not guarantee a 16:9 display: the actual flex layout and available
height change its rectangle. The implementation therefore reads the video
rectangle and intrinsic dimensions synchronously on each input, without cached
layout, orientation listeners, React resize state or Canvas-backing assumptions.

## Small repair and preserved interfaces

`clientPointToVideo` uses scale `min(cssWidth/videoWidth, cssHeight/videoHeight)`
and subtracts centered margins before normalization. For the independent fixed
640×480 → 960×540 reference this gives content 720×540 and horizontal offset
120; client (300,405) becomes normalized (0.25,0.75). Exact edges are inclusive;
points immediately outside are rejected rather than clamped onto an object.
Nonfinite inputs, zero/negative dimensions, unavailable video and underflowed
geometry return before hit testing. Client rectangles already include viewport
offset and scrolling; no page-offset or DPR multiplication is applied.

Only these five executable files change:

- `src/services/videoCoordinates.ts`: pure conversion and margin/validity guards.
- `src/components/VisionCanvas.tsx`: read live video geometry in the click handler;
  keep the same normalized point for engine selection and ripple.
- `src/services/videoCoordinates.test.ts`: 40 independent geometry cases.
- `src/components/VisionCanvas.test.tsx`: six component regressions; make mock
  intrinsic dimensions configurable and give the existing click test a video
  rectangle as well as its old Canvas rectangle.
- `e2e/coordinates.spec.ts`: two actual-app/native-video cases using the existing
  explicit E2E SDK alias, network isolation, pixel and Canvas-arc observations.

Drawing, mask alpha/polygon/BBox selection precedence, tracking IDs, speech
policy, camera acquisition, model lifecycle, scheduler, metrics, dependencies,
lockfile and workflows are unchanged. No mirroring was introduced. Existing
tests/assertions remain, including initial frame handling, VideoFrame/quality/
pixel compatibility, duplicate suppression, owning JobLock and generations,
exceptions/recovery, truthful FPS and latest drawing props.
