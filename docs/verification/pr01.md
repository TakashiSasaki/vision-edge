## Product-code scope and deferred issues

Product edits only remove unused imports/bindings/parameters and an overwritten
initial empty-array assignment. State setters and their effects remain in place
to preserve rendering behavior. Vite's `__dirname` becomes ESM `import.meta.dirname`
under the required Node version. Camera acquisition/stop code, inference scheduling,
tracking, model implementation, FPS calculations, and UI remain unchanged.

There is one targeted `react-hooks/exhaustive-deps` exception on the existing
VisionCanvas render-loop effect. Adding the captured `drawOverlays` function or
`clickRipple` to its dependencies would change animation/inference-loop restarts.
It is deferred to lifecycle/inference/UI work rather than changing behavior in
this infrastructure PR. No global rule is disabled and no test asserts this bug
as intended behavior.

Known deferred issues with reproduction/context:

- **Dictionary fallback (observed in a direct service probe):**
  `getLabelInfo('carpet')` returns the car translation because of substring
  matching; `typeof getLabelInfo('constructor')` is `function` because inherited
  object properties are accepted as dictionary entries. Tests cover valid exact
  labels and a real unknown fallback (`quantum widget`), without specifying those
  defective cases as correct. Harden dictionary lookup separately in PR-06.
- **Model/backend truthfulness (source-confirmed):** select YOLO-seg or SegFormer,
  then inspect `detectVideoFrame`: both use MediaPipe ObjectDetector plus generated
  polygons. Selecting another backend changes `resolveBackendLabel`, while model
  initialization still requests the GPU delegate. PR-02 should reconcile these
  advertised capabilities; smoke tests check UI selection only.
- **Camera lifecycle (source-confirmed; real-device reproduction not executed):**
  with the camera active, cause a parent re-render (for example change the selected
  model). App supplies a fresh inline `onCameraStop`, which is a dependency of the
  webcam effect, so cleanup and acquisition can repeat. Late getUserMedia completion
  also lacks a cancellation guard. PR-03 must exercise and repair these paths.
  The denied-camera smoke test cannot establish healthy stream lifecycle behavior.
- **Overlay closure (source-confirmed; device reproduction not executed):** tap
  an already-selected detection without changing other render-loop dependencies.
  The loop can retain the previous `clickRipple` because it captures `drawOverlays`
  without tracking that closure. The targeted lint exception preserves this
  pre-existing behavior for PR-04/06 review.

Unit tests use jsdom, a mocked MediaPipe loader, denied camera permission, and a
null canvas context for App rendering. The browser test executes the real built
app with denied camera permission and all external requests blocked. Real devices,
camera frames, GPU/model inference, accuracy, tracking geometry, FPS semantics,
speech playback, and comprehensive accessibility are untested. No later roadmap
phase is implemented or certified here. PR-02 can proceed after independent review
of this foundation and resolution of any hosted CI blocker reported in the PR.
